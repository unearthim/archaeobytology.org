I. The Master Field Report Template

A complete archaeological field report documents every stage of your work—from initial discovery through final Anvil output. This template integrates all seven chapters into one structured document. Use it for every excavation.

Master Field Report Structure

Section 1: Discovery & Initial Documentation

Source: Chapter 1 (Deep Excavation)

  • Artifact Identification: What did you find? (URL, file path, physical description)
  • Discovery Context: Where/how was it discovered? (Archive search, personal collection, public repository)
  • Excavation Method: Which protocol did you use? (Boolean construction, network analysis, cultural keywords)
  • Initial Assessment: First impressions of significance, completeness, condition

Section 2: Forensic Analysis & Material Reading

Source: Chapter 2 (Forensics & the Tangible Archaeobyte)

  • Technical Specifications: File format, size, encoding, metadata, creation date
  • Material Signatures: What does the format reveal? (Platform assumptions, technical philosophy)
  • Five Forensic Questions: What does it encode? Reveal? Obscure? Require? Resist?
  • Format Philosophy: What argument does this artifact's structure make?

Section 3: Custodial Filter & Ethical Review

Source: Chapter 3 (The Custodial Filter)

  • Privacy Assessment: Does it contain PII? Anonymization required? Consent status?
  • Copyright Analysis: Who owns it? Fair use applicable? Orphan work status?
  • Ethics Testing: Three questions: Should it be preserved? Public? Cited?
  • Clearance Decision: PROCEED / PROCEED WITH MODIFICATIONS / DO NOT PRESERVE

Section 4: Triage & Classification

Source: Chapter 3 (Three-Axis Diagnostic)

  • Technical Legibility: YES / NO / CONDITIONAL (explanation)
  • Functional Integrity: YES / NO / CONDITIONAL (explanation)
  • Contextual Ecosystem: YES / NO / CONDITIONAL (explanation)
  • Classification: VIVIBYTE / UMBRABYTE / PETRIBYTE (with edge case notes)

Section 5: Preservation Strategy

Source: Chapter 4 (Preservation Strategies)

  • Preservation Method: Emulation / Migration / Hybrid (rationale)
  • Technical Implementation: Tools used, environment created, transformations applied
  • Verification: How was success confirmed? What works? What doesn't?
  • Archive Location: Where is it stored? Redundancy strategy? Access policy?

Section 6: Close Reading & Wisdom Extraction

Source: Chapter 7 (The Anvil - Close Reading)

  • What does it PROVE? (Vivibyte lesson - resilient principles)
  • What does it WARN? (Umbrabyte lesson - failure modes)
  • What does it REMEMBER? (Petribyte lesson - extinct functions)
  • What does it ARGUE? (Forensic lesson - encoded philosophy)
  • What does it ENABLE? (Anvil question - intervention possibilities)

Section 7: Anvil Output & Publication Plan

Source: Chapter 7 (The Anvil - Output Paths)

  • Output Path Selection: Monument / Landmark / Synthesis (rationale)
  • Production Plan: What will you build? Timeline? Resources needed?
  • Publishing Strategy: Where will it live? Owned ground confirmed? Licensing?
  • Citation Plan: How will sources be documented? Primary sources listed?

Section 8: Conclusion & Broader Significance

  • Summary of Findings: What did this excavation reveal?
  • Contribution to Field: Why does this matter? Who benefits?
  • Future Work: What questions remain? Next excavations needed?
  • Lessons Learned: Methodological reflections, challenges overcome

This eight-section structure ensures comprehensive documentation. Every excavation should produce a field report following this template. It becomes your portfolio, your proof of work, and your contribution to the discipline's cumulative knowledge.

II. Pre-Flight Checklist: Before You Excavate

Before beginning any excavation, run through this checklist. It prevents methodological errors, ensures ethical compliance, and saves time by catching issues early.

The Archaeobytologist's Pre-Flight Checklist

1

Define Your Research Question

What are you looking for? Why? What will you do with what you find?

⚠️ Without a clear question, excavation becomes aimless collecting.

2

Choose Your Excavation Protocol

Boolean search? Network analysis? Cultural keywords? Match method to target.

⚠️ Wrong protocol = low yield. Review Chapter 1 if uncertain.

3

Confirm Ethical Clearance Intent

Will you be able to publish this? Any obvious PII concerns? Copyright red flags?

⚠️ Don't waste time excavating unpublishable artifacts.

4

Prepare Documentation Tools

Field Report template ready? Screenshot tools installed? Note-taking system set up?

⚠️ Document as you go. Retroactive documentation misses details.

5

Confirm Preservation Capacity

Do you have storage space? Emulation tools? Migration software if needed?

⚠️ Don't excavate what you can't preserve.

6

Plan Your Anvil Output

What will you build with this? Monument, Landmark, or Synthesis? Where will it live?

⚠️ Excavation without Anvil plan creates archives that become morgues.

✓

Ready to Excavate

All six items confirmed? Begin your field work. Document everything.

This checklist takes 10 minutes but saves hours of wasted effort. Treat it as mandatory pre-flight procedure. No excavation begins without completing all six checks.

III. The Archaeobytologist's Toolkit

Effective archaeological work requires appropriate tools. This section recommends software, services, and resources for each stage of the workflow. All recommendations prioritize open-source or vendor-neutral options to avoid platform dependency.

Excavation Tools

  • Internet Archive Wayback Machine - Primary excavation site for archived web content. Learn advanced search operators.2
  • archive.org Collections - Software, audio, video, text archives. Specialized collections for specific eras/platforms.
  • GitHub Archive Search - Code archaeology. Search by language, date range, stars, forks.
  • Google Advanced Search - Date range filters, file type operators, site-specific searches for surface-level discovery.
  • Old Web Resources - Wiby.me (indexed pre-2000s sites), Neocities (contemporary hand-built web), GifCities (GeoCities GIF archive)

Forensic Analysis Tools

  • HxD Hex Editor (Windows) or Hex Fiend (Mac) - Examine file structure at byte level.
  • ExifTool - Extract metadata from files (creation dates, software used, embedded info).3
  • File Format Documentation - FileFormat.info, Library of Congress Digital Preservation formats registry.
  • MediaInfo - Technical details for video/audio files (codecs, bitrates, container formats).
  • DROID (Digital Record Object Identification) - UK National Archives tool for format identification.

Preservation Tools

  • Emulation: Internet Archive's Emularity - Browser-based emulation for DOS, Apple II, Commodore 64, arcade games.
  • Emulation: DOSBox / DOSBox-X - DOS environment emulation. Essential for 1980s-90s software.
  • Emulation: QEMU - Full system emulation for various architectures/OSes.
  • Migration: Pandoc - Document format conversion (Markdown, HTML, PDF, DOCX, etc.).
  • Migration: FFmpeg - Audio/video format conversion and normalization.4
  • Version Control: Git + GitHub - Track changes, maintain redundancy, publish code-based monuments.

Anvil Production Tools

  • Monument Building: HTML/CSS/JS - Learn fundamentals. Monuments require hand-coding for sovereignty.
  • Monument Hosting: Netlify / Vercel / GitHub Pages - Free static hosting with custom domains.
  • Domain Registration: Namecheap / Porkbun / Cloudflare - Own your ground. Avoid platform-bundled domains.
  • Synthesis Writing: Markdown + Static Site Generator - Obsidian, Jekyll, Hugo for owned blog infrastructure.
  • Citation Management: Zotero - Open-source reference manager with web clipper.5

Documentation & Organization Tools

  • Note-Taking: Obsidian / Notion - Linked notes for building knowledge graphs of excavations.
  • Screenshots: ShareX (Windows) / CleanShot (Mac) - Document what you find visually.
  • Web Archiving: ArchiveBox - Self-host your own archive of discovered artifacts.6
  • Spreadsheets: LibreOffice Calc / Google Sheets - Track excavations, build inventories, compare findings.

This toolkit prioritizes tools that respect your sovereignty—open-source where possible, vendor-neutral always, export-friendly universally. Build your practice on tools that won't become Umbrabytes themselves.

IV. Your First Excavation Assignment

This is your certification exercise. Complete this assignment to demonstrate mastery of the 200-level curriculum. You will conduct a full excavation, document it using the Master Field Report Template, and publish an Anvil output on owned ground.

ASSIGNMENT: Complete Field Report + Anvil Output

Objective

Excavate one significant Archaeobyte, document it through all seven workflow stages, and produce a publishable Anvil output. Your submission must include: (1) Complete Field Report following the Master Template, (2) Published Anvil output (Monument, Landmark, or Synthesis), (3) Reflection essay on lessons learned.

Requirements

  • Artifact Selection: Choose an Archaeobyte NOT covered in course case studies (no GeoCities homepages, ICQ, RSS feeds as primary focus)
  • Documentation Rigor: All eight sections of Field Report Template must be completed with evidence
  • Ethical Clearance: Must pass all three custodial filters (or document why modifications were needed)
  • Triage Classification: Defend your Vivibyte/Umbrabyte/Petribyte classification with three-axis diagnostic
  • Anvil Output: Must be published on owned ground (your own domain or guaranteed-export platform)
  • Citation Practice: Minimum 8 academic sources + proper primary source citations for the Archaeobyte itself

Suggested Artifact Categories

If you're unsure what to excavate, consider these fertile territories:

  • Web 1.0 Subcultures: Webrings, guestbooks, hit counters, animated GIFs, textfiles, ASCII art
  • Early Social Media: Friendster profiles, MySpace layouts, LiveJournal communities, Usenet groups
  • File Format Fossils: .SWF Flash files, .WAV tracker modules, .NFO scene releases, .HLP help files
  • Platform Extinctions: Google+, Vine, Delicious, StumbleUpon, Tumblr (pre-2018 adult content purge)
  • Interface Petribytes: Clippy, Windows 95 desktop themes, Winamp skins, Firefox extensions (pre-Quantum)
  • Gaming Ecosystems: Flash game portals, GameSpy servers, forum-based clans, mod communities

Evaluation Criteria

Your submission will be evaluated on:

  • Methodological Rigor (30%): Did you follow all protocols correctly? Is documentation complete?
  • Analytical Depth (25%): Is your close reading insightful? Did you extract meaningful wisdom?
  • Ethical Practice (15%): Did you handle custodial issues appropriately? Citations proper?
  • Anvil Execution (20%): Is your output well-crafted? Does it match the insight? Published correctly?
  • Scholarly Contribution (10%): Does this advance the field? Is it publishable quality?

Submission Format

Submit three components:

  1. Field Report PDF: 3000-5000 words following Master Template structure. Include screenshots, technical diagrams, and all documentation.
  2. Anvil Output URL: Live link to your published Monument/Landmark/Synthesis on owned ground. Must be publicly accessible.
  3. Reflection Essay: 500-1000 words discussing: What you learned, challenges encountered, how methodology evolved, what you'd do differently next time.

This assignment is not busywork—it is your first published contribution to digital archaeology as a discipline. Approach it with the same rigor you'd bring to any scholarly publication. Your field report could become a cited source for future archaeologists working in your chosen territory.
