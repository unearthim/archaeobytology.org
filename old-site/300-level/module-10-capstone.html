Module 10: Capstone Project - Build or Preserve

Duration: 4 weeks Type: Portfolio Capstone

Module Overview

This is where everything comes together.

Your capstone project is your final act as an archaeobytology student—and your first act as a practitioner. You will either build a sovereign system or preserve a dying platform. This isn't a simulation. This is real work that matters.

By the end, you'll have a portfolio piece demonstrating your ability to do archaeobytological work in the world.

Learning Objectives

1. Apply all course concepts: Integrate Archive & Anvil thinking 2. Execute real preservation work: Not hypothetical, not theoretical 3. Build something that lasts: Infrastructure, not just ideas 4. Document your process: Create replicable methods 5. Present professional work: Portfolio-quality deliverables

Choose Your Path

You must choose ONE of these two tracks:

Track A: Build a Sovereign System

Build something new that embodies the Three Pillars of Digital Sovereignty.

Requirements

Your system must demonstrate: - Declaration: Users understand what it does and doesn't do - Connection: Users can leave with their data and relationships - Ground: System can survive without you or a company

Project Options

Option 1: Sovereign Communication Tool - Build a decentralized chat/forum/social tool - Must support data export - Must be self-hostable - Must have clear terms and transparency

Examples: Mastodon client, Matrix server, email newsletter tool with portable subscribers

Option 2: Digital Preservation Infrastructure - Build tooling to help others preserve their digital lives - Must be accessible to non-technical users - Must produce portable, standard formats - Must include documentation

Examples: Social media archive tool, personal website backup system, family photo preservation pipeline

Option 3: Educational Platform - Create a sovereign learning environment - Students must own their work and data - Must support federation or export - Must have ethical governance

Examples: Portfolio system students control, peer-to-peer learning tool, educational commons platform

Option 4: Community Infrastructure - Build digital infrastructure for a specific community - Must be controlled by that community - Must respect digital sovereignty principles - Must be sustainable without you

Examples: Local mesh network, community radio streaming, neighborhood wiki, mutual aid coordination system

Deliverables

1. Functional Prototype - Working code (GitHub repo required) - Deployment instructions - User documentation - Technical documentation

2. Sovereignty Audit (5-7 pages) - Evaluate your system against the Three Pillars - Identify compromises and why they were necessary - Explain design decisions through sovereignty lens - Assess sustainability and maintenance plan

3. User Guide - How to use your system - How to self-host (if applicable) - How to export data - How to fork/modify

4. Presentation (15 minutes) - Live demo of your system - Design decisions and tradeoffs - Sovereignty analysis - Future development roadmap

Track B: Preserve a Dying Platform

Choose a dying or recently-murdered platform and execute a real preservation project.

Requirements

Your preservation must include: - Forensic Documentation: Murder profile and analysis - Technical Preservation: Actual data capture and archiving - Metadata & Context: Sufficient documentation for future understanding - Access & Ethics: Clear policies on who can access what

Project Options

Option 1: Community Archive - Preserve a community's content from a dying platform - Work with community members (get consent!) - Create accessible archive interface - Document community history and context

Examples: Preserve a Tumblr fandom, archive a subreddit facing deletion, save a Discord server's history

Option 2: Cultural Documentation - Document a dying platform's culture before it vanishes - Interviews, screenshots, data analysis - Create comprehensive record for future archaeobytologists - Explain what made it culturally significant

Examples: Document TikTok subculture before potential ban, preserve MySpace aesthetics and culture, record Discord community practices

Option 3: Technical Preservation - Archive platform infrastructure or codebase - Preserve tools, APIs, or technical artifacts - Document technical architecture - Make it possible to study or revive later

Examples: Archive API documentation before shutdown, preserve custom themes/plugins, save technical specifications

Option 4: Personal/Family Archive - Preserve someone's digital life from a dying platform - Could be your own or (with permission) a family member's - Create portable, future-proof archive - Design for longevity and accessibility

Examples: Extract decade of Facebook memories, preserve blog archive, save family photos from dying service

Deliverables

1. Preserved Archive - Actual archived data (stored securely) - Metadata and documentation - Access interface (if applicable) - Storage and sustainability plan

2. Murder Profile (8-10 pages) - Comprehensive analysis of platform death - Apply Custodial Filter to preservation decisions - Document methodology and tools used - Assess what was saved and what was lost

3. Preservation Documentation - Technical process (how you captured data) - Tools used and why - Challenges encountered - Replicable methodology for similar projects

4. Ethics Statement (3-5 pages) - Who gave consent for preservation? - What privacy protections are in place? - Who can access this archive and why? - Long-term custodianship plan

5. Presentation (15 minutes) - Show the archive - Explain preservation decisions - Discuss ethical considerations - Share lessons for future preservationists

Timeline

Week 1: Planning & Scoping

- Choose your track and project - Submit project proposal (2-3 pages) - Get instructor approval - Begin initial work

Week 2: Build/Preserve Phase 1

- Core implementation or preservation work - Check-in meeting with instructor - Peer feedback session

Week 3: Build/Preserve Phase 2

- Continue main work - Begin documentation - User testing or community feedback (if applicable)

Week 4: Polish & Present

- Finalize deliverables - Complete all documentation - Prepare presentation - Present to class

Assessment Rubric

Technical Execution (40 points)

- Functionality (20 pts): System works / Archive is complete - Quality (10 pts): Professional-grade work - Sustainability (10 pts): Can outlive the semester

Conceptual Integration (30 points)

- Archive & Anvil (10 pts): Demonstrates understanding of framework - Sovereignty/Preservation (10 pts): Applies course principles - Critical thinking (10 pts): Makes thoughtful tradeoffs

Documentation (20 points)

- Technical docs (10 pts): Clear, replicable, complete - Analysis (10 pts): Thoughtful reflection on process and decisions

Presentation (10 points)

- Clarity (5 pts): Communicates project effectively - Demo (5 pts): Shows actual work, not just slides
